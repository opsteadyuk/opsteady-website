Yamazumi / Line Balancing

This module builds a yamazumi chart, a simple stacked bar chart showing the actual work content at each station on a line or cell, and uses it to rebalance that work so it sits closer to takt, the target rate the line needs to run at. Yamazumi is a Japanese word meaning to pile up or stack, and the chart does exactly that: it stacks each station's individual work elements into a single bar, so every station's total load sits next to every other station's, measured against the same horizontal takt line.

Common questions

Isn't a busy-looking line already a balanced line?
No, and this is the core misunderstanding the whole module exists to correct. A line can be running flat out and still delivering below takt, because the work isn't evenly spread between stations. Busy is not the same as balanced, and the only reliable way to tell the difference is to chart real, observed work content station by station. See Pro section 2.
Do we need a full time-and-motion study to build this chart?
No. A stopwatch and a simple template are enough. This module is deliberately scoped below a full industrial-engineering time-study system, and the aim is a chart your own team can build and keep current, not one that requires a specialist. See Pro section 2 and section 4.
Can we build the chart from our written job instructions instead of watching the line?
No, and doing this is one of the most common ways the module fails. A written standard often no longer matches what actually happens on the floor, and a chart built from it describes a line that doesn't exist. The chart has to come from direct, current observation. See Pro section 9's first failure and section 16's first failure.
What if the overloaded station is being run by someone with years of experience? Doesn't that mean the problem is them, not the work?
Not necessarily, and this is worth checking carefully before assuming it. A yamazumi chart measures work content, not the person doing it. An overloaded station would be overloaded for anyone standing in it. Treat an overloaded bar as a design finding first, and only look at individual factors separately, after the work content itself has been checked. See Pro section 16's seventh failure and section 17.
What if a rebalance means moving work to someone who doesn't currently have the skill for it?
Check the Skills Matrix before finalising that move. Either build a short training plan into the trial period, or choose a different rebalancing move that fits the skill coverage you actually have right now. See Pro section 14's variant and section 18's third fork.
