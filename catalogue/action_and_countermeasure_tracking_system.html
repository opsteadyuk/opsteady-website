Common questions

We already track actions in the tiered meeting board and the LPA checklist. Why do we need a separate register?
Because those boards track actions inside their own routine, and an action opened in a Gemba walk or a problem-solving session has nowhere consistent to live once that routine ends. This module isn't replacing those boards, it's the single place every action lands regardless of which routine generated it, so nothing depends on someone remembering which board to check. See Pro section 2.
Isn't this just a project plan?
No, and keeping that boundary is the whole point of this module staying thin. A project plan sequences dependent tasks toward a defined deliverable. This register tracks independent, mostly short actions through to verified closure, each one usually unrelated to the others. If you find yourself sequencing dependencies or tracking a deliverable across the register, that work belongs in a project plan or an A3, not here. See Pro section 2 and section 11.
What are the six fields, and can we drop any of them?
Action, source, owner, due date, status and verification. All six are required. Drop verification and "done" becomes whatever the owner says it is, which is exactly the failure mode this module exists to prevent. Drop source and you lose the ability to see which upstream routine is generating the most actions, which is often the more useful signal. See Pro section 5.
What counts as a committed action versus an open idea?
A committed action has an owner and a due date, agreed at the point it's logged. If either is missing, it isn't ready for this register yet, it's still an idea, and it routes to the Idea & Suggestion System (P7.3) until someone takes it on with a date attached. See Pro section 17, fork 4.
Who verifies a closed action, the owner or someone else?
Someone other than the owner, always. Self-verification is the single most common way this module quietly stops working, because the person closing the loop and the person doing the checking need to be different people for the check to mean anything. See Pro section 15's first failure.
