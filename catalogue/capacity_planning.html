Common questions

What if we haven't confirmed our constraint yet?
Don't build this module yet. Run Bottleneck Analysis Tool first, and wait for a confirmed constraint rather than a suspected one. A capacity plan built around a guess is worse than no plan at all, because it looks authoritative while pointing at the wrong thing. See guide section 4.
How is this different from Bottleneck Analysis Tool?
Bottleneck Analysis Tool finds and confirms the constraint. This module takes that confirmed number and builds a plan around it, comparing it to real demand, sizing the gap, and recording a decision about what happens next. One finds the constraint, the other plans around it. See the guide's opening distinction.
What if demand keeps changing faster than we can review the plan?
That's the Pro depth note on demand-supply alignment, a lightweight, more frequent reconciliation cycle for sites where demand is genuinely volatile, rather than the standard trigger-based review. See guide section 14.
Our constraint shifts depending on which product we're running. Does this module handle that?
Yes, as a Pro variant. Build the plan per relevant product-mix scenario rather than a single static capacity figure, starting with the two or three scenarios that actually recur most often. See guide section 14 and section 17.
What if the gap shows headroom rather than a shortfall?
Record it anyway. A constraint with more capacity than current demand requires is still worth showing on the plan, since demand can grow into that headroom, and the plan should reflect the real ceiling either way. See guide section 5's minimum decision fork.
