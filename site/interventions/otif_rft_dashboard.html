Common questions

FAQ

We already have an OTIF number. Do we have to throw it away and start fresh?

No, and doing that would waste a number that might already be right. Run the audit path instead of the build-from-nothing path: same questions on the Definitions tab, but used to check what your existing number is silently assuming rather than to invent a new one. Most of the time the finding isn't that the old number was wrong, it's that nobody had ever written down what it was actually measuring. See guide section 5.

Our RFT number is going to drop once we're honest about scope. Is that a problem?

It's the opposite of a problem, it's the correction working. A number that goes down because the definition got more accurate isn't a regression, it's the first honest reading of where you actually stand. What matters afterwards is that the new definition stays fixed, so next month's number means the same thing as this month's. See guide section 17.

How does this relate to Root Cause Analysis Toolkit and Non-Conformance Tracker & Trend Pack?

Both are built, and the relationship is sequential, not parallel. This dashboard shows RFT dropping; Non-Conformance Tracker & Trend Pack (P3.1) is what answers why, with a ranked cause; Root Cause Analysis Toolkit (P7.5) is what verifies that cause, one step further downstream, not a second branch off this dashboard directly. A persistent Pareto cause surfaced here is the trigger for a logged non-conformance on P3.1's own tracker, not something this dashboard logs itself. See guide section 10.
