Common questions

FAQ

Is this a full project management methodology?

No, deliberately not. It's the minimum a genuine first-timer needs to run a real project properly, a one-page plan with an objective, scope, milestones, ownership and a definition of done. It isn't trying to teach formal project management, only to stop the most common ways an unstructured project goes wrong. See guide section 1.

How is this different from Kaizen Event Planner & Charter Pack (P7.2)?

They're not competing products. This teaches the general skill of running any project. Kaizen Event Planner applies that same underlying discipline specifically to a focused improvement event. Learn the mechanic here, apply it there. See guide section 9.

How is this different from Managing Change That Sticks (E2)?

A project plan and a change plan are different documents doing different jobs. This module delivers a defined piece of work with a scope and an end. E2 navigates resistance to a change already underway. A single piece of work can genuinely need both, run as two separate documents, not merged into one. See the boundary note at the top of the guide.

Why does "out of scope" matter as much as scope itself?

Because scope creep rarely happens through one big decision, it happens gradually, through things nobody explicitly decided were included. Writing out-of-scope items down explicitly is what prevents the most common way a project quietly grows past what it was actually meant to deliver. See guide section 4 and section 12.

What if we don't have a real project to practise on yet?

Wait until you do. A hypothetical project teaches the mechanic but nothing about it sticks. The habit only earns its place once it's run against something genuinely sitting on the desk. See guide section 4 and section 15.
