Common questions

FAQ

Our finance team already has a "cost of quality" number. Do we need to replace it?

No, and trying to would likely be the wrong move even if it were possible. Most finance-tracked cost-of-quality figures are narrower than they sound, often scrap value alone. Run the audit path: use the same Definitions tab questions to check what the existing number is actually including, then either adopt that scope here or clearly label this tool's figure as the wider one. The two should never both be called "cost of quality" in the same conversation without a stated scope attached. See guide section 5 and section 17.

We're time-poor. Do we really need to run both logs from the start?

No, and the guide says so directly. Run the Cost of Quality Log alone first, it's the sharper financial argument and the one most likely to get budget released for the wider effort. Add the Waste Log once that habit holds. This is a genuine, named fork, not a compromise. See guide section 4 and section 18.

A defect got logged as both a waste cost and a failure cost. Doesn't that double the number if we add the two totals together?

Yes, which is exactly why the tool tells you not to add them together. Cross-reference the row on both logs when a Defects waste entry and a Failure cost entry are the same event, and read the two totals side by side rather than summed. This is the one point the two frameworks genuinely meet, everywhere else they're independent. See guide section 16, failure 5.

How does this relate to Root Cause Analysis Toolkit and Overtime & Agency Spend Tracker?

Both built. Root Cause Analysis Toolkit (P7.5) is genuine downstream: a persistent Internal or External Failure cause, or a top waste category that hasn't moved, is exactly the kind of named finding it already takes from Non-Conformance Tracker and Downtime Tracking, and the reciprocal line lives on its own Works With too. Overtime & Agency Spend Tracker (P8.2) turned out not to be downstream at all once checked: it's a sibling P8 cost log with its own separate routing (absence, capability, capacity, breakdown, planning), never into this tool, so it's filed as related, different lens, not a hand-off. A third candidate, Labour Planning & Shift Pattern Model, was checked and dropped entirely, nothing in its own file supports a link and it doesn't fit this tool's subject matter. See guide section 10.
