Overview

Most critical tasks on a manufacturing floor are learned the same informal way: watch someone experienced do it a few times, then have a go while they check in occasionally. It feels efficient, and for a while it is, but it quietly produces as many versions of "the right way" as there are experienced people teaching it — each with their own shortcuts and their own unspoken reasons for a step that never gets said out loud because it's obvious to them. The gap doesn't show up immediately; it shows up weeks or months later as a quality escape traced to a step nobody mentioned, an unexplained pace difference between two operators doing the same job, or a scramble when the one person who really knows the task is off sick.

This module turns one operator's task into a teachable, followable job instruction, using the same watch, write, read-back, correct method Set Standards (F2) already uses, applied to a single critical task. It uses a format close to TWI Job Instruction, breaking the task into important steps, the key points that make each step succeed or fail, and the reason behind each key point — because a step alone doesn't transfer well, but a step with its reason attached does.

Done properly, the result is one short, specific job instruction for one critical task, written so a new person can be taken through it in a single training cycle and actually retain it — not a full procedure with every exception documented. It's finished only once it's been trial-taught to a second person who can then perform the task to standard without the original expert standing over them.

At a glance
Time

Half a day to a day to capture one task properly, from watching the work to a trial-taught instruction — spread across a few sessions rather than one long sitting, since the work needs watching at a normal pace more than once.

Who's involved

Whoever's capturing the instruction, the person who currently does the task best, and one other person willing to be trial-taught from the draft before it's finalised. For your own site, decide: who decides which task gets captured first; who's doing the capturing, and whether they have protected time to do it properly; who signs off that the finished instruction matches what's actually done — the operator, the supervisor, or both; and who updates the instruction when the process changes, and how they find out a change has happened.

What you'll need

The job instruction template, and Set Standards (F2)'s register if one already exists, so the finished instruction has somewhere to be logged. The working file, P1.7_Operator_Standard_Work_Job_Instruction.xlsx, two tabs: a Job Instruction tab (the three-column format, task, capturer, date and sign-off, with a key point refused if it has no reason attached, and an automatic check against the 4-to-10 important-step band) and a Standardisation Register tab logging which tasks have been captured, by whom, and whether trial-taught and confirmed.

Before you start

Start with one task, chosen because it's flagged as a risk on the Skills Matrix (only one person qualified) or because it's a known source of defects — not because it's the easiest one to capture. Watch the actual work at its normal pace, more than once if the cycle is short. Draft the instruction, then read it back to the person who does the task and correct it until they confirm it's genuinely right, not just plausible. Trial-teach it to one other person before treating it as finished — an instruction that's never been used to actually teach someone is unproven.

If a standard for this task already exists in Set Standards (F2), turn that into the teachable format rather than re-deriving it from scratch; if not, capture it from scratch and consider feeding the confirmed result back into F2's register.
