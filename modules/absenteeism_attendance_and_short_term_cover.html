Absenteeism, Attendance & Short-Term Cover

Today's absence covered by a decision, not a scramble — logged against who's qualified and what it costs, so the same expensive gap stops repeating unnoticed.

£179Buy now
Overview

When someone calls in sick, cover usually gets decided fresh, on the spot, by whoever's around — with no reference to who's actually qualified, what each option costs, or whether the same expensive fix has already been reached for three times this month. The shift gets covered, so it feels solved, but nobody can say whether it was the right call, and because nothing gets written down, the same gap can be covered the same costly way repeatedly without anyone noticing it's a pattern rather than isolated bad luck.

This module is a decision tool, not a tracking sheet for its own sake: who's off, who's qualified to cover — pulled straight from the Skills Matrix contingency register — the cost of each option, and the decision made, logged. It deliberately reuses Skills Matrix's own contingency-register logic rather than building a new mechanic, just applied on a much shorter fuse: the same question Skills Matrix answers for planned absence, asked again for someone who's off today.

Every cover decision leaves a trace the next one can be checked against, and a monthly trend review turns individual entries into a visible pattern — surfacing a repeat gap as the structural issue it actually is, so it can be escalated to Labour Planning & Shift Pattern Model instead of being quietly absorbed as normal.

At a glance
Time

About an hour to build the cover-decision sheet structure. After that, near-zero setup — each entry takes minutes at the point an absence actually happens.

Who's involved

Whoever makes cover decisions day to day, usually the supervisor on shift, and whoever owns Skills Matrix for the area, since this module depends entirely on that contingency register being current. For your own site, decide: who logs the decision at the point an absence happens, and how quickly; who reviews the absence trend monthly, and what counts as a pattern worth escalating; and who owns taking a repeat gap to Labour Planning & Shift Pattern Model once it's been seen more than once.

What you'll need

Skills Matrix in use for the area, so qualified cover options are already known rather than guessed at each time — without it, this module has nothing real to pull from and reverts to the same guesswork it's meant to replace. The working file itself: P1.5_Cover_Decision_and_Absence_Trend.xlsx, two tabs — a cover-decision sheet (one row per absence, working out the cheapest qualified option, the cost difference against what was actually chosen, and how many times that role has needed cover in the last 90 days) and an absence trend log.

Before you start

Confirm Skills Matrix is current for the pilot area first — this module has nothing real to work from without it. Start in one area, wherever absence cover is currently costing the most or causing the most stress, not a site-wide rollout on day one. Then wait for the next real absence, not a hypothetical one, and log it properly: who's off, the qualified options, the cost of each, the decision made.
